为什么隐指令那三步必须由硬件来做

这三步夹在“用户程序最后一条指令做完”和“服务程序第一条指令开始”之间。这个空档里没有任何一段软件在为这次中断干活：用户程序不知道中断来了，服务程序还没开始跑，能动手的只有 CPU 的电路。

① 关中断。IF 就是 PSW（x86 里叫标志寄存器 EFLAGS）里的一位，1 表示 CPU 接收 INTR 送来的中断。如果把关中断交给服务程序自己写一条 CLI，“进入服务程序”和“关上中断”就成了先后两件事，中间有没有空子可钻，要看 CPU 在哪设检查点、每个服务程序是否都记得第一句写 CLI。硬件在响应的同一个动作里把 IF 清 0，保证后面保存断点、保存现场的过程不会被新中断打断。

② 保存断点、切内核态。软件想保存 PC，就得执行一条“把 PC 存起来”的指令，可这条指令在服务程序里，CPU 要先跳转到服务程序才能执行它，一跳转 PC 就已经被改掉了，原来的值找不回来。所以只能由电路在装入新 PC 的同时把旧 PC 存进内核栈。PSW 同理，而且 IF 就在 PSW 里：这里存下的是响应前 IF = 1 的样子，返回时恢复 PSW，IF 自然回到 1。切内核态更不能交给软件：用户程序若能自己切换，任何程序都能给自己升权限。硬件只在“跳到操作系统指定的入口”这一刻顺带切换，入口不是用户程序选的。

③ 取类型号、查向量表、跳转。跳转之前 CPU 还停在用户程序里，没有哪条软件指令会去跳到服务程序，只能由电路取来类型号、查表、装入 PC。表是操作系统事先填好的，用户程序改不了，这也保证了跳到哪里由内核说了算。

返回时反过来。IRET 要一次性恢复 PC、PSW 和模式位。如果先把模式切回用户态，下一条还在内核里的指令就会因权限不够出错；如果先恢复 PC，CPU 已经跳回用户程序，剩下的恢复指令再也执行不到。所以返回也只能是一条由硬件原子执行的指令。

分类总表：中断、异常，以及两套归类
中断（外中断）异常（内中断）
来源CPU 执行指令之外的事件由当前这条指令引起
例子键盘、磁盘完成、时钟；电源掉电（NMI）缺页、除以 0、非法操作码、特权指令违规、syscall
同一程序再跑一遍发生位置会变必在同一条指令上发生
是否经中断控制器INTR 经过；NMI 不经过不经过，CPU 内部产生类型号
能否屏蔽INTR 可以（IF、屏蔽字）；NMI 不能一律不能
何时响应当前指令执行完，在检查点响应（NMI 也要等）当场处理，不等指令完成
异常的三类故障 Fault自陷 Trap终止 Abort
性质意外出错，可能修复程序故意安排硬件故障
例子缺页、除 0、溢出、非法操作码、特权指令违规系统调用、条件陷阱指令、断点 int3内存校验错、控制器出错
处理后返回第 i 条（重新执行）；无法修复则终止程序第 i+1 条不返回，程序终止

二次归类：软件中断 = 故障 + 自陷；硬件中断 = 终止 + 外中断。终止按“内 / 外”分是内中断，按“软 / 硬”分是硬件中断。

用户态进入内核态只有四种情形：① 系统调用（自陷，主动）；② 外中断；③ 程序执行中的异常（如缺页、除 0）；④ 企图执行特权指令。返回用户态由内核执行特权指令 IRET 完成。

响应条件、隐指令与服务程序九步（计组）

CPU 响应可屏蔽中断的条件：有未被屏蔽的有效请求；IF = 1（NMI 和异常不看 IF）；当前指令已执行完（只有异常不等）。请求还要先过设备接口自己的“中断允许触发器”。

步骤动作谁做
①②③关中断；保存断点（PC、PSW）；引出服务程序（向量法：取类型号查表）硬件（中断隐指令）
④保存现场（通用寄存器）和屏蔽字软件
⑤开中断（单重中断省略）软件
⑥执行服务程序本体软件
⑦关中断（单重中断省略）软件
⑧恢复现场和屏蔽字软件
⑨开中断 + 中断返回软件发起，IRET 由硬件原子执行

断点 vs 现场：断点是 PC（和 PSW），由硬件保存；现场是通用寄存器，由服务程序自己 PUSH / POP。向量地址、中断向量、向量中断：类型号 × 表项长度 = 向量地址；向量地址里存的是中断向量（服务程序入口）；整套“按编号查表跳转”的方式叫向量中断。

响应优先级由判优电路焊死，决定“先跳进谁的入口”；处理优先级由屏蔽字决定“进门后谁能打断谁”，可以动态改（见场景 5）。

现状更新

中断控制器：8259A 已被 APIC 取代，能把中断分发到多个核心。MSI：PCIe 设备不再用专门的请求线，而是往一个特殊地址写一小段数据来报告中断，不受引脚数量限制。

陷入指令：int 0x80（走完整的查表流程，约 1000 个周期）已被 syscall 取代（入口预存在 MSR 寄存器里，约 100 个周期）。本页按教材模型画成“查向量表 0x80”。

上半部 / 下半部：服务程序关着中断运行时，别的设备的请求只能在控制器里排队。更糟的是，接口的中断请求触发器只有一位：同一台设备在这期间又来一次请求，只是把已经是 1 的位再置一次 1，两次合成了一次，等于丢了一次。所以关中断的时间越短越好。Linux 把服务程序拆成两段。以网卡收包为例：上半部在关中断的状态下，只把包从网卡搬进内存、告诉网卡“收到了”，再记一笔“有包待处理”，几微秒就返回；下半部稍后在开中断的状态下慢慢做剩下的事：检查包是否完整、交给对应的程序。下半部运行期间，新的中断随时能进来。

多核：CLI 只把执行它的那个核心的 IF 清 0。四核机器上，核 0 关了中断、正在往键盘缓冲区里写，核 1 照常运行，它上面的程序可能同时在从这个缓冲区取字符，两边一起改就乱了。关中断挡得住本核的服务程序插进来，挡不住别的核。所以还要一把锁：内存里放一个变量，0 表示没人在用。谁要改缓冲区，先把它从 0 改成 1，改成功才能进去，用完改回 0；别的核看到是 1，就原地反复查看，等它变回 0，这叫自旋锁。“看到是 0 就改成 1”必须由一条不可拆的原子指令完成（如 x86 的 xchg），否则两个核可能同时看到 0，都以为自己拿到了锁。

代价：8086 响应一次中断约 61 个周期；现代 CPU 流水线更深、要保证精确中断，常在数百个周期量级。
